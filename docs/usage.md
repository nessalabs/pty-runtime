# Embedding and ownership

Keep one `Runtime` alive for the lifetime of the sessions it owns. Construct it
on the process main thread **before** starting a multithreaded async executor or
other worker threads: construction forks to stage the helper image, and platform
atfork handlers can deadlock if another thread holds a lock. A `Session` is a
control/observation handle; dropping it or an `Attachment` leaves the child
running. Dropping the runtime terminates its children and joins its workers.
`shutdown()` does this explicitly and synchronously. Reconnect with `lookup(id)`
and `attach(AttachPosition::Cursor(cursor))`; neither operation spawns a child.
Completed IDs remain reserved until `forget(id)`. A reused ID has a new lifetime,
and old cursors cannot address the replacement session.

Choose `SessionOptions::raw(size)` for bytes alone or
`SessionOptions::projected(TerminalConfig::new(size))` for an authoritative native
terminal. The `ghostty` default feature supplies the native adapter. Raw builds
use `--no-default-features`; injected terminal adapters also work without Ghostty.
The public application ports are available through `pty_runtime::ports`.

For a usable local shell client, see the [interactive terminal example](examples/interactive.md).
It forwards input/output and window resizing through a real raw session and restores
the host terminal during cleanup.

## Replay and projection

Raw replay is a finite tail, independent from lossless parser staging. A slow
observer receives an exact gap followed by retained bytes. A raw cursor counts
original PTY bytes within one lifetime. It cannot be used as an event-store cursor
or as a terminal mutation sequence: resizes consume no output bytes.

`projected_view()` obtains an admitted copy of current terminal state.
`terminal_checkpoint()` obtains a compatible binary snapshot.
`begin_transfer()` captures a checkpoint and an ordered output/resize observer
at one boundary. Apply its original bytes and resizes to a compatible consumer
model in sequence, and discard replies generated by that consumer; only the
server's authoritative model may write terminal replies to the PTY.
`ResyncRequired` means capture a new checkpoint and continuation. Retained views,
checkpoints and events retain their quotas until dropped; cloning a borrowed
buffer makes a separate caller-owned allocation.

Projected sessions park after sixty seconds without output or another model
mutation by default. Process ownership, input, cancellation and PTY draining
continue independently. A parked immutable checkpoint can serve transfer without
restoring a native model. Restoration reports readiness separately from history
completion and interleaves queued live work with bounded history steps. Native
pages made inapplicable by live mutation are counted explicitly; a finished
source with skipped pages is not complete history restoration. See
[verification.md](verification.md) for what has been checked so far.

For raw sessions use `resize`; for projected sessions use `resize_projected` so
OS size and model state are ordered and partial outcomes remain visible. A write
wait reports actual bytes written and a possible failure. Dropping that wait
does not undo bytes or authorize a retry of the whole input. Cancellation is
owned once admitted. Completion preserves actual child exit, supervision errors
and output drain separately; truncated drain is not EOF or a successful exit.

## Bounds and storage

`RuntimeOptions` sets shared session, observer, input, replay and projection
ceilings; `SessionOptions` sets local limits. Completed registry entries and
surviving handles can still consume admission. Set both shared and local budgets
for the intended population. Defaults are policy ceilings, not a demonstrated
512-session capacity claim. Account separately for replay, parser staging,
terminal allocations, copied views, checkpoint pins, ciphertext, worker stacks,
allocator retention, kernel PTYs, workloads and Guardian processes.

The built-in disk store uses a fresh private namespace and a runtime-owned
in-memory encryption key. `StorageOptions` selects its trusted parent and logical
ciphertext ceiling. It does not restore running sessions after owner restart.
Normal teardown removes owned objects and the namespace. Default construction
also performs bounded crash cleanup inside a private versioned arena. Directory
locks distinguish live owners from abandoned namespaces; no PID inference or
recursive deletion is used. The disk adapter exposes `cleanup_abandoned` with
`CheckpointCleanupLimits` and an explicit report for larger maintenance passes.
Every incomplete scan blocks new admission, including exhaustion among live owners.
The default namespace scan ceiling is 256; increase finite cleanup limits or reduce
the live population to obtain a complete scan. Known abandoned work that exceeds
the deletion budget also blocks new admission.
Legacy directories outside the arena are not discovered or deleted. The empty
arena itself remains as bounded coordination metadata for that configured parent.
See [projection / parking behavior](features/projection-parking.md) for limits.
An injected `ICheckpointStore` must obey immutable
object, bounded read, commit and cleanup contracts; it never receives plaintext
from the default protector.

## Security and platform integration

The host supplies authentication, authorization, transport and access policy.
Launch roots constrain canonical working directories; they are not a child
filesystem sandbox. Commands run with the host account's authority. Choose an
explicit command/environment policy and treat terminal output as sensitive.
Diagnostic formatting redacts commands, environment values, payload bytes and
checkpoint contents. Applications must apply their own policy to displayed or
persisted output.

The Unix adapter embeds a separately built Guardian executable, materializes it
privately and starts it through a fresh exec. Each session has two persistent
helpers in addition to its workload. Ordinary finite same-session foreground and
background jobs are the cleanup scope; session escape and unbounded hostile
forking are outside that guarantee. Platform process/descriptor limits still
apply. Guardian costs are measured via process fixtures and the load harness;
see [`features/guardian-helper-image.md`](features/guardian-helper-image.md).
and remaining failure/distribution qualification. macOS/Linux arm64 and x86_64
are targets; only explicitly recorded runs establish tested coverage.

## Optional event-stream forwarding

Enable `event-stream` and pass an already-resolved stream incarnation, sink and
raw attachment to `EventStreamPublisher`. It creates no store or worker. Drive
`publish_next()` from your executor. One pending record retains the same identity
and payload across rejection, uncertain commit and cancellation; the PTY
acknowledgement advances only after a validated receipt. A newly created
publisher has a new identity and does not promise cross-publisher deduplication.
External store queues and retention have separate budgets.

Run the actual replay/gap/reconnect example:

```sh
cargo run --locked --example event_stream_reconnect --no-default-features --features event-stream
```

Resume event subscriptions from the event-stream subscription cursor, and decode
records to recover their original PTY byte positions. A stalled sink leaves raw
retention bounded and does not stop PTY draining or projection. Retrying a
publisher is a caller decision; capacity errors do not silently evict the store.

## Workspace service integration

The [workspace-sdk adapter sketch](examples/workspace-sdk-integration.md) maps
the inspected SDK boundaries and identifies the required target-side owner.
It is a proposed sibling integration, not an implemented transport.

A backend service can retain `Runtime` in its own long-lived state, map authorized
workspace/session IDs to `SessionId`, expose write/cancel/resize operations, and
create one admitted attachment per authorized transport connection. Persist no
claim that a session survived a service restart. Give disconnect and explicit
termination different handlers. On reconnect, validate the session lifetime and
choose raw replay or a new state transfer depending on the client model. Service
shutdown should call `Runtime::shutdown` before dropping the resources supplied
to its injected adapters.

## Internal measurement

Create `RuntimeDiagnostics::new()` and install it with `with_diagnostics` before
spawning a measured population. Its fixed shared histograms retain no session
labels or payloads. Read admission, actual PTY write, raw publication, ordered
terminal-feed publication, resize and cancellation dispatch separately. Success
percentiles use conservative 100-microsecond bucket bounds; overflow uses the
recorded maximum. Failures and uninstrumented boundaries have separate counts.
Take final snapshots after shutdown for consistent totals; concurrent snapshots
are approximate. Counters are cumulative. `reset_quiescent()` starts a new interval only after
the caller has stopped producers and settled every measured operation; it does
not pause the runtime, and concurrent reset invalidates the measurement.

Cancellation timing requires actual direct-workload and verified root/foreground
TERM acknowledgements. It includes acknowledgement transport, so it bounds OS
signal dispatch from above. A disappeared or unverified target yields no success
sample, and an incomplete measurement is counted at owner teardown. This does
not infer timing from process exit or from enqueueing a Guardian command. Fixture
round-trip latency and OS/kernel scheduling need their own measurements.

`aggregate()` reports fixed byte, gap, saturation, process-failure and cleanup
counters plus current unfinished-session, logical replay-retention, live-reader
and actual reader-scratch-capacity gauges. Reader capacity excludes allocator
overhead and stacks; observe settled readers before using it in memory attribution.
`resources()` reads the runtime's existing admission quotas, including active
observers, input, replay capacity, projection staging, native reservations,
checkpoint/storage/view buffers and continuation pins. These reservations are
not OS resident-memory measurements. Host escalation requests and observed
successful direct-workload SIGKILL syscall acknowledgements are separate
counters; neither reconstructs an acknowledgement from a member killed by its
own group-zero SIGKILL.
