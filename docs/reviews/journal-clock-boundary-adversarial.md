The test injects an IClock collaborator panic; it does not assert that arbitrary production callbacks must never unwind, nor that status remains usable after such a panic. ## Previously admitted waits: follow-up re-review

No P1/P2 finding in this exact delta. The arm-consumed assertion now distinguishes the intended IClock panic from an unrelated panic before the clock call.

The follow-up obtains completion and output waits through public Session/Attachment APIs and explicitly polls both to Pending before injection. After the same thread-targeted clock panic, each next poll must be Ready with the exact Internal error; synchronous try_next must also fail and the original attachment cursor must remain unchanged. These assertions distinguish an admitted wait from a new waiter rejected at registration and require that no rejected byte is published as an event. No sleeps, counters used as branching or private session fields are involved. The output borrow is dropped before inspecting its attachment, and all wait/attachment handles are dropped before shutdown checks Closed residency.

The test intentionally uses a noop waker and polls explicitly. The prior test separately exercises provisional new-waiter rollback and final context gauges. No stronger wakeup or immediate-release claim should be inferred from this follow-up.
