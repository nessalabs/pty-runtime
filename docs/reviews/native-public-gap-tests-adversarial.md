# Native terminal/materializer gap tests: adversarial review

Reviewed the exact additions to terminal_contract.rs, terminal_bounds.rs and the existing process_image_materialize fixture, the real terminal restore/materializer paths, and retained targeted logs. Independently verified all three test-source hashes in work/native-public-gaps/test-source-sha256.json against current files. No builds or tests were run by this reviewer.

No P1/P2 finding in this bounded delta.

Underline assertions use ordinary VT input and exact public cell decoration values, text and widths. Later indexing and cursor checks prevent a short/empty cell collection from vacuously passing the zip. Reset is followed by a new character while the first six complete cells must remain equal. The X10 case independently keeps SGR encoding enabled while toggling Press/None tracking; both screen cells and cursor must remain unchanged. These are observable terminal contracts, not checks against copied FFI representations or private discriminants.

Restore rejection starts from an authentic valid native checkpoint. One byte below its actual length must fail with BudgetExceeded and the exact length must succeed. A valid but mismatched size must fail specifically with InvalidConfiguration, then the original size succeeds. Checking the original view and subsequent equal source/restored feeds rejects accidental source mutation and verifies useful restoration after the failed attempt. The small no-history fixture does not establish all incremental history-restoration cases or independently measure native allocation counts; those are not claimed by these tests. Source inspection confirms the local native owner is dropped on dimension rejection.

Materializer tests use its established write entry point with actual filesystem failures. The chmod-0500 parent tests PermissionDenied while preserving an existing sibling and leaving no destination; restoring permission then retrying proves the owned path remains usable. The NUL case checks InvalidCommand, intact prefix bytes and unchanged directory membership, followed by a valid write. Full calling-thread signal membership is checked after each attempt; no process-global signal disposition or shared host resource limit is modified. Random private directories isolate concurrent tests, and Directory::Drop restores owner write permission before cleanup on both normal and unwind paths. The existing signal-mask guard remains in scope through retries and restores the original thread mask on exit.

PermissionDenied depends on normal unprivileged DAC enforcement. The recorded uid-501 run supports that case; root/capability-bypassing or unusual ACL environments are not covered by this result. No conditional skip or permission-error weakening was introduced. The NUL case exercises pre-fork validation, while the protected-parent case exercises the actual child open failure; neither fabricates internal state or adds a failure hook.

Retained terminal.log reports all 12 terminal tests passed; materializer.log reports all six materializer tests passed. The author reports formatting passed. Source-level and targeted evidence is bounded acceptance of these tests, not a replacement for the post-change mechanical/performance/coverage gates or proof of complete native/platform coverage.
