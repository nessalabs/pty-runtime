# Terminal ABI faults: independent adversarial review

Reviewed the final five-file terminal change read-only: `src/terminal/{mod,faults,projection,state}.rs` and `tests/fixtures/terminal_faults.rs` under `crates/infrastructure`. All five current hashes match `work/terminal-native-faults/source-sha256.json`. No P1/P2 finding remains in this scope. The separately authored process materializer syscall seams are outside this review.

The injected state is compiled only for tests, remains thread-local, rejects nested arms, is non-Send, and clears on Drop. Every behavioral fault requires exact consumption. The independent thread's join now occurs outside the deliberate panic catcher, so a cross-thread leak cannot masquerade as the expected scope-cancellation panic. The retained cancellation test verifies a subsequent real read and re-arming after unwind.

Each seam runs after the actual native operation. Malformed metadata requires a successful real read and initialized output storage; it changes an enum/scalar boundary value without inventing private terminal state. The long-grapheme case uses 65 actual codepoints to trigger the real native small-buffer response and allocation retry. It does not manufacture a length or bypass the retry. Read failures return no view and permit an unchanged successful read and later feed. Mutating failures occur after a native call may have changed state and require the owner to reject all further mutating/read/checkpoint/history operations. Fresh owners remain usable.

Restore metadata failure constructs the normal temporary owner before the failing query, so ordinary Drop frees it; source and retained checkpoint remain reusable. History failure keeps checkpoint storage alive through failed-owner Drop. The native history implementation clears its decoder pointer when it finishes, and native free checks that pointer, so replacing a successful history result cannot produce a second decoder free. This is source reasoning about ownership, not a measured native allocation census.

Retained evidence records nine fault tests passing and 18 existing native integration tests passing, including the 100,000-line history restoration case. The first unsupported-compression assertion failure remains in `native-faults-attempt01.log`. The revised test correctly accepts actual compression progress, requires bounded completion, and verifies unchanged view plus subsequent feed; it does not waive the intended recovery behavior. Production-library Clippy and scoped formatting logs pass. This reviewer ran no builds or test processes.

These cases establish Rust adapter handling of ABI errors and malformed native responses after real native calls. They do not establish native allocator-failure behavior, exact allocator leak counts, impossible arithmetic branches, or 100% coverage. Fresh canonical collection and the other independent gates remain necessary for broader acceptance.
