# Idle control memory evidence assessment

The completed frozen candidate-3 evidence does **not yet establish** the ADR-0002 ≤4 KiB per-session control-memory upper bound. This is an evidence gap, not a demonstrated memory regression. Read-only source and completed-file assessment; no source changes, builds or workloads. Exact source/file identities and arithmetic are retained in `docs/verification/release/idle-control-memory-assessment/evidence.json`.

All five completed idle-64 runs have requested Rust live bytes 904,656 at `runtime` and 1,325,948 at `ready`: delta 421,292, or 6,582.6875 bytes/session. Subtracting 64 live 4,096-byte scratch allocations would leave 159,148 total, or 2,486.6875 bytes/session. That subtraction is currently conditional, not proven. Corresponding completed raw-resource conditional results are 3,989 bytes at one session, 2,491.375 bytes/session at 32, and 2,490.53125–2,492.15625 at 128. Repetition demonstrates reproducibility of the aggregate values; it does not identify allocations.

## Ownership and evidence boundary

- `ProcessLimits::default` requests a 4,096-byte read chunk. `process/io.rs:17` allocates its `Vec<u8>` within the reader thread, before polling; the local buffer is held through reading, clearing and drain delivery. Its requested payload would be scratch, separately accounted under the ADR.
- `process/registration.rs:44` starts the reader but does not wait for that allocation. `process/supervisor.rs:30` replies with the process handle after thread creation. The fixture readiness frame comes over a separate Unix control socket (`population.rs`), not through the PTY reader. Neither successful spawn, child readiness, elapsed warmup nor a thread census establishes that each scratch allocation is already present at the sampled checkpoint. No scratch-live counter or reader-start acknowledgement is recorded.
- `Population::new` creates `children` with session capacity **before** the runtime checkpoint. Its backing storage is already in the baseline and must not be subtracted again from the delta. Observer-vector allocation occurs later; with zero observers its outer storage is fixture overhead included conservatively in the delta. Do not replace measured ownership with `size_of<Child>` guesses.
- Every idle-64 ready budget records zero replay capacity, queued input bytes/slots and projection usage. Configured MiB limits are logical ceilings, not allocations; none is a valid subtraction. Raw sessions instantiate no terminal model. The scratch allocation is not represented by those budgets.
- Runtime construction also precedes the baseline, including process admission channels sized from `max_sessions`, projection registry/scheduling reservations when composed, diagnostics and shared owners. The recorded baseline varies with population capacity. ADR permits a **measured shared baseline**, but it must be reported with configured capacity and fixture contributions; the ready-minus-runtime number alone is not total runtime-owned memory and cannot be presented as a universal population-independent shared cost.
- The fixture allocator measures requested Rust heap bytes, not malloc size-class overhead, C allocations, committed/reserved stacks, helpers, kernel PTYs or child memory. Those categories cannot be inferred by subtracting RSS from these numbers. Relaxed live counters and concurrent workers also do not provide a quiescent allocation-class ledger.

## Minimal missing proof

For a subsequent authorized run, establish and record a checkpoint barrier after each live reader has allocated scratch, retaining a live scratch count/actual requested-byte total through the snapshot. A dedicated diagnostic allocation counter or explicit reader-start acknowledgement is the direct proof. A PTY-output handshake could establish execution, but it must drain retained output and restore the intended no-payload idle state before sampling; a control-socket handshake alone cannot do this.

Pair that checkpoint with actual requested-byte classification of runtime shared reservations and fixture allocations, or a quiescent baseline demonstrating unchanged shared/fixture ownership across the delta. Report shared capacity-dependent baseline separately, charge unclassified incremental bytes conservatively to control state, subtract only classified live scratch/payload allocations, and retain the physical stack/allocator/kernel/helper categories separately. This would make the attractive 2.49 KiB conditional arithmetic reviewable; the existing records must remain conditional. Census and zero logical-budget observations do not prove repeated lifecycle reclamation or 12-hour stability.
