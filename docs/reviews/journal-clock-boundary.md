# Journal delegation and public clock failure boundary

The seven journal poison-recovery closures only invoked the standard library's `PoisonError::into_inner`. They now pass that function directly. This removes redundant adapters without moving lock acquisition, changing guard lifetimes, changing error policy, or excluding any application source from measurement. Recovery still returns the same protected state. No custom guard, callback, or error conversion was changed.

The separate clock test starts from public runtime composition and process event ports. The verified production path is `SessionEventSink::output_observed` (`runtime/context.rs`, state lock) → `ProjectionCoordinator::stage_output_observed` (`projection/admission.rs`) → `AdmissionQueue::admit_output` (`projection/queue.rs`, admission lock) → injected `IClock::now` before output policy admission commits. The test clock panics once on the calling thread only, so background scheduler reads cannot consume the fault. Its own mutex is released before panic.

The test confirms the actual callback panic, then checks the existing typed failure policy: session status and waiter admission return Internal, later process output returns Closed, and waiter admission returns its provisional observer reservation. No published or processed bytes, raw replay reservation, staged bytes or staged slots remain. Runtime shutdown still closes the projected session, releases its native reservation and terminal owner, and never feeds the rejected bytes. Dropping the public owner and session returns active-session and replay gauges to zero.

This public-port test passed before the journal cleanup. The panic is an injected collaborator failure; it does not establish a newly discovered production defect or a behavior fix. It exercises context/admission recovery and resource ownership, not the unrelated journal poison path. Existing private poison tests were neither added nor extended.

Evidence is retained in ignored `work/journal-clock-boundary`: `clock-before-cleanup.log` preserves the injected failure and passing invariants; `application-final.log` and `integration-final.log` record the final affected suites. The initial affected run passed 152 application tests and eight integration tests, including real PTY/Ghostty behavior. Independent quality/adversarial review and the full mechanical/coverage gates remain separate requirements.

Quality review identified that catching any panic alone did not prove the clock was the source. The test now immediately asserts that the one-shot clock arm was consumed. The focused rerun passes in `clock-quality-rereview.log`; no production policy changed. Independent closure of that finding is tracked in `journal-clock-boundary-quality.md`.

A separate follow-up test covers previously admitted completion/output waits (`runtime/session.rs:131`, `runtime/attachment.rs:105` in the V12 inventory). Both are Pending before the same public clock failure and must return Ready(Internal) on their next explicit poll; the attachment cursor stays unchanged and synchronous reads also fail explicitly. This does not claim autonomous waker notification after a callback panic. Existing assertions are retained. Build verification is pending coordination with the profiling lane.
