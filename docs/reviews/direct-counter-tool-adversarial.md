## What the oracles require

The standalone fixtures do not call the runtime implementation or mirror its counter algorithm. `normal_and_panic.rs` exercises normal true/false arms, repeated calls, an early return, loop body/continue/break, and a caught panic in an ordinarily typed boolean condition. `process_exit.rs` exercises an ordinarily typed condition that exits the process with status 23, including a caller above that condition. The expected stdout sequence and exit status were fixed before compilation.

Each named `observe` call emits and flushes an explicit side-effect record. The validator checks the full source export at both the call token and its literal argument. Every observed path must have its exact multiplicity; every named never-executed sibling/continuation must have count zero. Missing mappings fail, and no source region is excluded or edited to repair a summary. Saturation absence is only one check, never the acceptance criterion.

Both stock and direct builds use the same source, atomic profile-counter option, opt-level 0 and selected compiler/sysroot. This controls the atomic-update variable rather than attributing a difference to the wrong mechanism. Both process-exit binaries actually exited 23 with only the three declared pre-exit observations. Both panic fixtures returned zero after the expected caught panic and emitted the exact declared sequence.
