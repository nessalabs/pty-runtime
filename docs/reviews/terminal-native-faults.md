# Terminal ABI fault boundaries

User-authorized test-only injection targets the remaining terminal error guards in `work/coverage-closure/full-current-continuous02/workspace.json`. Every selected native call still runs against the real pinned Ghostty owner. `#[cfg(test)]` post-call interception replaces an exact result code or a validated initialized output field. No public fault API, runtime feature, environment switch, domain hook, production branch, or test-only owner constructor is added.

Faults are one-shot and thread-local. A non-Send RAII guard rejects nested arming, records exact consumption and clears the slot on Drop. Each behavioral case asserts consumption. Mutation error injection intentionally occurs after the native operation may have changed state; tests require the adapter to reject every subsequent operation on that owner. Read-only errors must permit the same owner to return the unchanged view afterward. Scope cancellation before invocation is separately tested.

The boundary cases are: info and row-query errors; initial cell and actual long-grapheme retry errors; invalid Unicode scalar, foreground/background/underline color tags and underline enum; feed/resize/compression mutation errors; checkpoint error with successful retry; restore metadata failure without a returned partial owner; history restore budget failure; and recoverable unsupported compression. Metadata modifications require a successful real call and initialized bounds. The long grapheme produces the native small-buffer failure and actual allocation retry; the seam never fabricates a required length. Public descriptor mismatch and compression during restoration need no injected fault.

Quality review found that the initial thread-isolation test caught the child join assertion inside the deliberate cancellation-panic catcher. That could accept a child failure as the intended panic. The test now requires the child join to succeed outside the catcher, drops that isolation guard, and separately catches only the deliberate unwind scope.

The first execution passed eight tests and failed the unsupported-compression recovery assertion: the real native adapter returned Ok(true), correctly reporting compression progress. The test incorrectly required immediate Ok(false). It now requires successful bounded completion within 128 calls on the small-screen corpus, unchanged view, and subsequent successful feed. No production bug or behavior change is claimed. `work/terminal-native-faults/native-faults-attempt01.log` retains the failure; `native-faults-final.log` records all nine fault tests passing.

The existing native contract, bounds, view-edge and checkpoint/state suites pass all 18 tests, including the 100,000-history-line restoration case; see `native-existing.log` in that evidence directory. Terminal-file formatting passes. Full workspace formatting remains a separate gate while unrelated process fault files are being authored concurrently. Independent reviews are pending final source and evidence inspection.

Limits: these tests establish API error, reuse and failed-owner semantics, not an allocator-level native leak measurement. No skipped-page counter overflow is manufactured; the `u64` checked-add failure remains unexercised. The final compression expression after `mutation(nonzero)?` is logically unreachable and is not forced by changing control flow. Allocation-exhaustion and impossible arithmetic guards remain distinct from native ABI failures.
