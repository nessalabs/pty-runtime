# Additional helper protocol cases: authoring record

Added three scenarios to the existing scripts/guardian/probe.py under the coordinator's explicit assignment. The original eight functions/classes, including all original scenario implementations and Session, compare AST-identically with HEAD; existing 20 scenarios and assertions remain. No helper/runtime implementation or measurement tooling changed.

The TERM-only case admits the actual helper, waits for a workload that has installed TERM/HUP ignore handlers, and checks its real SID, PGID and foreground group. It sends exactly one Terminate record to the guardian endpoint while both owner sockets remain open. It sends no owner Kill, Release or Abort before success assertions. The guardian endpoint must provide exactly one SignalApplied `[workload, SIGTERM, 7, 0]`, then Escalated `[workload, SIGKILL, 0, 0]`, then WorkloadExit carrying that workload's actual SIGKILL wait status. Every received exit record must agree. Both channels must close, the actual child must be reaped, no Fault/StartFailed may appear and no live process may remain in its SID. The global outside-session control from the existing suite must remain alive. Grace is one second; existing bounded five-second waits provide scheduling headroom. The workload has no competing timed exit or descendant that could be mistaken for the root.

The Execute failure cases wait for both helper Hello records, then send Execute for a fresh missing path or a mode-0600 file. Both endpoints must deliver exact StartFailed `[ENOENT/EACCES, 0, 0, 0]`. Neither Started, Admitted, WorkloadExit nor Fault may appear; there must be no workload output or established workload identity. Both endpoints and actual child terminate, and the SID has no live members. The existing file contains an observable output command so accidental execution cannot silently count as rejection.

New-case teardown occurs only after assertions or on failure. It invokes the established Abort/owner-EOF cleanup path; a finally block closes remaining owner/PTTY descriptors and, if still necessary, kills and waits at most five seconds for the actual Popen child. It does not signal cached numeric groups. Teardown cannot satisfy a success oracle because session completion, actual status and absence of live session members are required first. Catastrophic helper cleanup failure remains a failing case; the test does not claim graceful cleanup can always recover arbitrary broken helper code.
