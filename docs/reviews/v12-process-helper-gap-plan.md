# V12 process/helper coverage gap inventory

Read-only adversarial inventory of retained V12 exports and existing public contracts. No tests, prototypes, builds or measured programs were added. The implementation lane remains with the coordinating author.

## What the two populations establish

The canonical V12 run completed its workspace/helper test commands, with the coordinator reporting unchanged sources and 45,710 tool/cache inputs. The retained workspace export measures 9,965/10,535 lines, 1,029/1,104 functions and 23,402/27,028 regions. Its standard helper population measures 476/1,478 lines, 62/109 functions and 1,143/3,687 regions. These are below the required thresholds.

The earlier continuous V9 helper collection exercised 17 unit tests and 20 actual protocol scenarios. Its complete export measures **1,430/1,682 lines (85.0178%), 113/121 functions and 3,438/4,476 regions**. Separately reconciling physical files yields helper src plus shared protocol 1,226/1,478 lines, 101/109 functions and 2,791/3,687 regions; external test modules contribute 204/204 lines, 12/12 functions and 647/789 regions. The first subtotal includes inline tests and is not production-only coverage. Independently rechecked all 27 original V9 source-manifest entries against current files: all still match. V9 remains historical diagnostic evidence, not a substitute for V12 calibration/current complete collection. Its outer driver failed a denominator inventory assertion after successful units/probe/merge/export; that failed command must stay recorded.

Probe20 already covers normal exit, guardian/sentinel loss, guardian abort, reserved guardian/sentinel groups with topology damage, owner EOF before/after execution, and handoff loss before/after acknowledgement. It does not send normal Terminate or Kill commands. Existing workspace tests separately cover cancellation, foreground switches, retained EOF, reader failure, helper loss, image validation and teardown against packaged helpers. Their helper-internal counters are not included merely because the workspace tests passed.

## Workspace process gaps requiring care

The largest process file gap is image_materialize.rs (104 uncovered lines). Many zero regions are the successful fork-child child_write path followed by `_exit`, including lines 67–77 and 186 onward. Existing bundled-image staging and materializer-abort tests already exercise those public effects. Standard profile shutdown cannot establish that these child paths did not execute. Reconcile process-boundary counter persistence before adding duplicate staging tests.

Other process files have smaller gaps: guardian 25 lines, io 24, backend 22, spawn 15, lifecycle 13 and spawner 12. Some are test-configuration constructor branches; others are OS/thread creation, wait, poll or signal error arms. For example backend139–151 handles supervisor panic/thread-spawn failure, and materialize52–59 handles sigset/pthread failures. Ordinary valid public requests do not deterministically induce all these errors. Do not fabricate stale descriptor/private-state fixtures merely to mark those lines covered, and do not delete them from the denominator. If the goal requires deterministic evidence for such a branch, first establish an authorized observable failure seam and its real recovery contract, with separate review of any implementation change.

The inventory's candidate zero line ranges were obtained by joining raw regions across all function instances for the same physical source file and removing lines with positive regions. They identify review targets, not an alternative LLVM line-percentage calculation. A zero unit-binary instantiation does not imply an uncovered source function when its actual helper-binary instantiation runs. All official totals above come directly from retained aggregate exports.

## Acceptance boundaries

A new test must fail when the intended public effect or cleanup guarantee is broken, must bound its own failure cleanup, and must not let that cleanup satisfy its success oracle. No private-state filler, fixture-specific production branches, source exclusions, changed expected counts, or threshold reductions are proposed. Fresh measured execution, independent code-quality/adversarial reviews, affected quality checks and the full canonical gate remain required. This plan does not assert that the proposed cases close every remaining line or region.
