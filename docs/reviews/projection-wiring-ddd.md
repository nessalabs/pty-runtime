## DDD and dependency direction

**P2 — Session admission invariants are owned by application instead of domain (resolved independently).** `crates/application/src/runtime/owner.rs:62-75` validates process limits, observer count, initial model/PTY size agreement, feed/read compatibility, parser staging limits, and reply/input/global capacity compatibility. These are pure relationships among domain values, with no adapter or runtime state involved. `crates/domain/src/session/mod.rs:SessionOptions` provides constructors but no cross-policy validation contract; consequently a domain consumer cannot validate the actual session admission rules without invoking the application use case. This conflicts with coding_standards.md's ownership of validated values/budgets and ADR-0005's domain ownership of admission rules. Move these predicates to a domain `SessionOptions::validate(&RuntimeOptions)` (or a similarly cohesive domain admission value). Keep the existence/capability check for installed projection adapters in application. Root moved these unchanged predicates into domain `SessionOptions::validate(&RuntimeOptions)` and application now invokes that before its adapter capability check. Independent regression `domain_session_validation_rejects_incompatible_projection_admission` exercises mismatched sizes, read/feed/staging limits, reply/input/global capacities and zero observers directly against the domain method. Both that test and the existing integration assertion that rejected policy never starts a child pass.

**P2 — Cleanup outcome erased at the ownership boundary (resolved independently).** The original `ProjectionRuntime::close` discarded `projection.close()`'s observation and returned `Ok(())` whenever residency became Closed (`projected.rs:45-55` in the reviewed pre-fix source). Closed means ownership ended, not that provider cleanup succeeded. Therefore `Runtime::forget` could silently remove a registry entry after exhausted deletion or an uncertain commit. Root added an atomic `close_outcome()` query and now returns that actual outcome both before closure and after each wait. Independent test `tests/projection_cleanup_outcome.rs` passes for permanent deletion failure and uncertain commit: first and repeated `forget` return a projection error, the registry entry remains inspectable, and residency is Closed. This test uses a completed fake process, fake terminal/store/protector, and actual scheduler/blocking adapters; it proves runtime orchestration, not real PTY/native/storage behavior.

Dependency direction otherwise holds within scope. The facade composes concrete Unix/native/file/crypto/scheduler adapters. Application stores I-prefixed process and scheduling/storage boundaries and domain values. Domain imports only standard-library and other domain modules. No external native pointer, OS handle, provider record or crypto implementation leaks into these core contracts. Keeping `ProjectionRuntime` as a concrete application ownership inventory is appropriate: its slots retain the same coordinator objects, rather than mirror domain policy or depend on caller repository reachability.

## Independent Clean Code / SOLID / cohesion assessment

The admission-policy finding above is also a responsibility defect in `Runtime::spawn`: it combines reusable policy validation with repository reservation and external process/model orchestration. Moving the pure predicates into domain resolves this without introducing a generic validator service or another dynamic interface.

`AdmissionGate` has a narrow synchronization responsibility; its guard owns in-flight spawn accounting and allows shutdown to wait without holding the admission mutex across external operations. `ProjectionRuntime::Reservation` reserves teardown ownership before native construction and rolls back unpublished slots. Both are appropriate concrete RAII patterns. `SessionContext` separates raw state, process ownership and projection ownership; the weak process event target avoids a process/context cycle. The separate facade adapter factory is an appropriate composition boundary. No additional P1/P2 cohesion, SOLID, service-locator, duplicate-state, or interface-design defect is confirmed in this scope.

The shutdown fallback is ordered after scheduler and blocking joins, preserving the explicit no-concurrent-native-work requirement. The injected scheduler's progress and finite provider-operation contracts remain necessary; this review does not claim support for an implementation that accepts work and then silently abandons it without any failure signal.
