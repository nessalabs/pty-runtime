# Independent protocol EOF fixture correction

Reviewed the failed raw-only infrastructure gate at `docs/verification/resumed/macos-gate-final/command.log`. `peer_reset_cannot_turn_a_partial_final_record_into_clean_eof` expected InvalidData from the second receive but got Ok(None). This is not evidence that the channel reported clean EOF: `Channel::receive` explicitly returns Ok(None) on WouldBlock/Interrupted, while `Channel::eof` remains false until finish_receive. The old fixture asserted the error before checking EOF readiness. Concurrent fork/exec tests can temporarily inherit peer descriptors, delaying the final close; the original log does not identify which descriptor owner caused this specific occurrence.

Changed only the cfg(test) module in scripts/guardian/protocol.rs. A five-second bounded helper waits for observable closure, rejects any unexpected complete frame, and propagates any error. Both partial-record tests still require InvalidData, so a timeout, clean EOF, or unrelated OS error cannot pass. The complete-record close test still requires its exact Retiring frame before waiting for clean EOF. The partial-reset test now deliberately retains a cloned peer descriptor, checks that repeated reads remain pending and eof=false, then closes the final descriptor and requires InvalidData plus eof=true. This directly exercises the distinction that the old fixture conflated without relying on scheduling a concurrent fork.

The test still queues Release without the peer reading it, writes the truncated final Retiring record and closes rather than shutting down the socket. Consequently it preserves the real Unix unread-control reset/EOF scenario; the correction neither mocks reset nor forces a clean shutdown that bypasses the Linux reset path. Production receive/finish_receive logic is byte-for-byte unchanged. This is a fixture correction, not a behavioral production fix; the original gate failure is retained and must not be relabeled production RED.

Executed on macOS: the five targeted protocol tests pass, then all 17 raw-only infrastructure library tests pass with the fork/image fixtures running in the same ordinary concurrent test process. Raw logs, exact commands, platform and source SHA-256 are in docs/verification/resumed/protocol-eof-fixture. Linux execution, the fresh complete gate and independent review of this test edit remain coordinator responsibilities. Source length remains below the 350 nonblank-line threshold.
