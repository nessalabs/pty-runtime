# Helper image concurrent-fork contract: test authorship

The new Linux-only unit test `constructor_image_executes_while_unrelated_child_is_between_fork_and_exec` requires the actual `HelperImage` constructor result to execute successfully while an unrelated child is paused before exec. **No local compilation or execution has occurred.** The coordinating agent will retain the Linux RED result before any production fix. `docs/verification/helper-image-fork-contract/source-before.json` captures exact pre-fix seam/test/source hashes.

A minimal cfg(test) observer runs at the existing constructor's actual writable-file creation before its normal write/chmod/return. `HelperImage::new` otherwise calls the same materialization logic; the observer parameter/call disappear in non-test builds. The callback carries no image descriptor or pathname and never opens or reopens the image. This allows the eventual implementation to expose the corresponding materialization handoff without requiring a writable parent descriptor after the fix.

The constructing parent starts an unrelated `/bin/true` Command on another thread. Its pre_exec closure acknowledges entry over an inherited socket, then gates exec using only raw write/poll/read/_exit with fixed stack data. No child-side Rust allocation, logging, locking or owner destruction is introduced. The parent waits for acknowledgement before the image constructor continues, forcing the pre-fix inherited-writer interval rather than relying on a probabilistic race.

After construction returns and releases its local writer, the test attempts to execute the real helper image. It then releases/joins/reaps the blocker **before** asserting constructor or execution results. Parent socket waits are finite, the child gate has a ten-second timeout, and spawned Child owners have bounded waits followed by kill/reap on cleanup. The coordinating Linux test command should retain its ordinary outer timeout as well. The same image is verified against the exact embedded bytes and executed again after blocker release. Invalid protocol invocation must exit 125, proving exec reached the real helper without launching a PTY workload.

The pre-fix expected observation is ETXTBSY (26) during the held interval and successful exec after release. The assertion requires success during the held interval; it does not bless ETXTBSY as expected production behavior. The untraced trial-37 initial-guardian ETXTBSY evidence independently establishes the affected syscall boundary; this forced interleaving proves this mechanism against the actual constructor, but is not a reconstruction of every instruction in that earlier run.

No finished read-only image is artificially reopened for writing, no generic OS-only stand-in replaces HelperImage, no retries/serialization/production workaround are introduced, and frozen release candidates remain untouched. Independent production/test review and RED/GREEN execution are still required.
